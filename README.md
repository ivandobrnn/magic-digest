# 🎩 Новинки фокусов в Telegram

Python собирает новые позиции из каталогов TCC Magic, Ellusionist, Alakazam Magic, Tannen's, Merchant of Magic, Magic Dream, Wizard Magic Shop, J&B Magic, 52Magic, IARVEL MAGIC и PITATA Magic. GitHub Actions запускает сбор ежедневно около 09:17 по Москве. Выпуск публикуется на третий календарный день после предыдущего, когда есть свежие карточки. Один выпуск состоит из максимум семи сообщений с общей датой.

## 1. Канал и бот

1. В Telegram создайте публичный канал и задайте ему имя пользователя, например `@magic_news_example`.
2. Откройте [@BotFather](https://t.me/BotFather), отправьте `/newbot`, задайте название и имя пользователя с окончанием `bot`.
3. Сохраните выданный токен. Храните его в GitHub Secrets. При утечке перевыпустите через BotFather.
4. В канале откройте **Управление каналом → Администраторы → Добавить администратора**, найдите бота и включите право **Публикация сообщений**.

## 2. Репозиторий

Распакуйте архив. Создайте пустой публичный репозиторий `magic-digest` на GitHub. Загрузите файлы из архива в его корень с сохранением папки `.github`. Для загрузки через Git откройте терминал в распакованной папке и выполните, заменив `YOUR_USERNAME` своим именем на GitHub:

```sh
git init
git add .
git commit -m "Add Telegram magic digest"
git branch -M main
git remote add origin https://github.com/YOUR_USERNAME/magic-digest.git
git push -u origin main
```

Если Git попросит задать имя и email автора, укажите их в настройках Git и повторите commit. В публичном репозитории стандартный Linux-раннер GitHub Actions бесплатен. Файл `state.json` будет виден вместе с кодом. В нём хранятся карточки, даты обнаружения, идентификаторы отправленных сообщений и журнал незавершённой отправки. Дайте workflow возможность записывать этот файл в основную ветку.

## 3. Секреты

В репозитории откройте **Settings → Secrets and variables → Actions → New repository secret**.

| Имя | Значение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | Токен от BotFather |
| `TELEGRAM_CHAT_ID` | Имя канала целиком, например `@magic_news_example` |

## 4. Проверка и запуск

В **Actions → Дайджест фокусов → Run workflow** доступны три режима:

- **preview** — собрать карточки и вывести их в журнале запуска. Это можно сделать ещё до добавления секретов.
- **test** — отправить одно тестовое сообщение в канал. История дайджеста при этом сохраняется.
- **publish** — выпустить дайджест сразу. После этого обычное расписание отсчитывает три дня от даты выпуска.

GitHub может задерживать запуск по расписанию. Проверьте, что workflow включён и его файл лежит в основной ветке. Если GitHub остановит расписание из-за неактивности репозитория, включите его в разделе Actions.

## Как выбираются карточки

- Первая подборка формируется из текущих витрин. Далее учитывается дата первого появления в системе. Дата релиза товара может отличаться.
- При выборе учитываются карточные фокусы, ментализм, электроника и гаджеты, close-up и реквизит, сценические иллюзии, магические приложения и обучение. Категория определяется правилами по заголовку, адресу и метаданным. Состав зависит от поступлений, поэтому некоторые категории могут отсутствовать.
- Точные URL и нормализованные названия сохраняются в истории. Разные названия одного релиза могут пройти как отдельные карточки.
- Фото берётся из метаданных страницы товара. Ссылки на YouTube или Vimeo извлекаются из страницы, когда они доступны. Для 52Magic также поддерживается прямая ссылка на размещённую магазином видеодемонстрацию. При отклонении фото Telegram отправляет текстовую карточку. При отсутствии новых позиций в пределах семи дней с обнаружения канал остаётся без выпуска.
- Ошибка одного магазина записывается в журнал. Другой магазин обрабатывается независимо. Если магазины поменяют разметку, проверьте `listings` и `details` в `digest.py`.

## Если отправка прервалась

Перед каждой отправкой workflow сохраняет `pending` в `state.json`. Это защищает от автоматического дубля, если Telegram принял сообщение, а GitHub потерял ответ или не успел записать результат. Сверьте `pending.key` с сообщениями в канале.

- Если карточка в канале есть, запишите её Telegram message ID в `items[ключ].published`, поставьте `last_issue` равным `pending.date` и удалите поле `pending`.
- Если карточки нет, удалите поле `pending` и запустите `publish`, чтобы продолжить публикацию.

После ошибки Telegram с определённым кодом отказа проверьте токен, адрес канала и права бота. Журнал выводит код отказа. После частичного выпуска можно продолжить через `publish`. Уже записанные в истории карточки пропускаются.
